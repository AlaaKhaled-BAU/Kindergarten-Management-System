Generated by an autonomous full-repo audit on branch `audit/full-repo-review`. Methodology: baseline commit of all pre-existing uncommitted work, then parallel deep-read of every source file (schema, all 11 server actions read personally, UI/RTL, Electron/build/infra, lib utilities) plus a dedicated over-engineering sweep. Every finding below is file:line-anchored and was verified by reading the actual code, not inferred from AGENTS.md claims alone.

**Bottom line: the app is not ready to ship as-is.** The core "does the packaged .exe even start" and "is the printed receipt amount correct" questions both currently fail. Nothing here is a rewrite — every item below is a targeted fix.

| 1 | [main/main.js:24-27](main/main.js:24) — spawns `process.execPath` (the Electron binary) as the standalone server with no `ELECTRON_RUN_AS_NODE=1`. ## P1 — High

- **Do first, adversarial-review-flagged as under-prioritized:** `createdBy` on `Transaction`/`Refund` is never populated (see below) — for a two-role Admin/Teacher system whose entire point is accountability, an unattributed ledger undercuts the whole premise of the P0-3/4/5 authz fixes (why lock down who-can-do-what if you can't later tell who-did-what). Fix alongside the auth cluster, not at the back of P1.
- **Upgraded from P2:** `Math.max(0, balance)` clamping (dashboard, ledger PDF, monthly summary PDF) silently floors overpaid families to a 0 balance. Kindergartens routinely take semester prepayments — this isn't cosmetic, it's a parent-facing printed document quietly hiding a real credit. Fix alongside P0-9's dashboard scoping work.
- [src/app/actions/student-actions.ts:168-243](src/app/actions/student-actions.ts:168) `updateStudent` never calls `logEvent`, unlike `createStudent`/`processPayment`/`cancelReceipt`. Fee/discount/grade changes that post an `Adjustment` transaction go completely unlogged — not an await-race like the logger.ts issue below, a total absence of a log call for a money-moving action.
- [src/app/actions/student-actions.ts:390-403](src/app/actions/student-actions.ts:390) `getDefaultTuition` and its duplicate in [promotion-actions.ts:104-111](src/app/actions/promotion-actions.ts:104) — ignore `Fee.academicYear` entirely and tie-break duplicate fee rows by cheapest `amount`. Harmless today (one fee row per grade), but the schema models per-year tuition specifically so next year's tuition increase can coexist with this year's — as soon as that happens, this silently picks the wrong (likely older/cheaper) row. Fix: filter by current `academicYear` too, extract into one shared helper instead of two copies.
- `createdBy` on `Transaction` ([schema.prisma:157](prisma/schema.prisma:157)) is never populated by any of the 3 call sites that create transactions. `requireAuth()` already returns the role — thread it through. Financial ledger with no actor attribution.
- `Refund` model ([schema.prisma:165-178](prisma/schema.prisma:165)) is fully modeled (indexed, has `createdBy` required) but has zero server action, zero UI, zero references anywhere. Either build the minimal flow or drop the table — see Enhancements below, recommending the former.
- `StudentFee` join table — never written to anywhere; `getStudentById`'s `fees` field is always `[]`. Same either-build-or-drop call as Refund.
- [src/lib/logger.ts:44-55](src/lib/logger.ts:44) — read-modify-write on the shared daily JSON log with no locking; several call sites (`login/actions.ts:31,37`, `payment-actions.ts:84,135`, `student-actions.ts:163`) don't even `await` it, so concurrent writes can silently drop entries. Fix: await every call site; consider append-only line-delimited JSON instead of read-whole-file-rewrite to remove the race entirely.
- [src/lib/excel-utils.ts](src/lib/excel-utils.ts) exports write user-supplied strings (student names, vendor, description) into cells with no sanitization — classic formula-injection risk if a value starts with `=`, `+`, `-`, `@`. Prefix such values with `'` before writing.
- `importRevenues`/`importExpenses` ([import-actions.ts](src/app/actions/import-actions.ts)) never call `logEvent`, despite AGENTS.md Phase 8 explicitly listing "imports" as required logging.
- English strings: [src/components/ui/sheet.tsx:75](src/components/ui/sheet.tsx:75) (`"Close"` sr-only text, reachable via the mobile nav) and [src/components/pdf/receipt-pdf.tsx:205](src/components/pdf/receipt-pdf.tsx:205) (`"No. "` prefix on a printed receipt). AGENTS.md: Arabic only, no exceptions.
- [src/components/layout/sidebar.tsx:94-103](src/components/layout/sidebar.tsx:94) — mobile nav renders both `SheetContent`'s own default close button and a second hand-built one. Pass `showCloseButton={false}` to `SheetContent`.
- Silent error swallowing on PDF generation: [report-tab-receipt.tsx:47-58](src/components/reports/report-tab-receipt.tsx:47), [report-tab-ledger.tsx:66-77](src/components/reports/report-tab-ledger.tsx:66), [report-tab-monthly.tsx:36-51](src/components/reports/report-tab-monthly.tsx:36) — `catch { setPdfData(null) }` with no visible message.
- No UI path exists to deactivate/withdraw a student (`deactivateStudent` in student-actions.ts has no caller anywhere in `src/components` or `src/app`).
- Missing indexes for the app's own hot paths: compound `(studentId, transactionDate)` on `Transaction` (ledger view + ledger PDF), `studentId`/`paymentDate` on `Payment` (`getUnpaidStudents`' N+1), `paymentId` on `Receipt`.
- No `.env.example` — AGENTS.md documents `DATABASE_URL`/`ADMIN_PASSWORD`/`KG_NAME` as required but a fresh clone has no template.

## Enhancements (explicitly in scope — "your touch")

Picking a small, high-value, low-risk set rather than everything imaginable:

1. **Build the minimal Refund flow.** Schema already has the table; this is a real kindergarten need (withdrawal mid-year, overpayment). Mirror `cancelReceipt`'s shape: a Server Action that inserts a `Refund` row + a negative-adjusting `Transaction`, inside `$transaction`, gated `requireAdmin`, plus a small UI entry point from the student ledger tab.
2. **Populate `createdBy`** on every Transaction/Refund using the already-available `requireAuth()` role — turns the dead schema field into a real audit trail with near-zero cost, and pairs naturally with fixing P1's createdBy gap.
3. **Scope the dashboard to the active academic year** with a lightweight year selector — fixes P0-9 and turns the dashboard into something that stays meaningful year over year instead of degrading.

Considered and deliberately **not** building this pass (documented, not silently dropped): global search-by-parent-phone, scheduled/automatic backups, a full audit-log viewer UI. Each is a real idea but adds new surface area beyond "fix what's here" — flagging for a follow-up rather than expanding this pass's blast radius.

## Explicitly deferred (flagged, not fixed here)

- **All money fields are `Float`.** Real cumulative floating-point drift risk for an immutable, append-only, SUM-based ledger. Fixing this properly means migrating every money column to integer fils (or `Decimal`), touching nearly every file — too large and risky to do unprompted inside this pass. Mitigation planned for this pass (not yet applied as of this writing — flagged by adversarial review that the original wording here wrongly implied it already existed): add a shared `roundMoney()` helper and use it at every sum/aggregate site to stop drift from compounding. Full migration recommended as a deliberate, separately-scoped follow-up.
